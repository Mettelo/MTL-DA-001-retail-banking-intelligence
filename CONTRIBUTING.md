# Contributing

## Purpose

GitHub is the primary technical collaboration and evidence environment for this project.

## Expected Workflow

1. Create or assign an issue for meaningful pieces of work.
2. Create a branch from the agreed base branch.
3. Make focused commits with meaningful messages.
4. Push work to the repository.
5. Open a pull request for material changes.
6. Request peer review where appropriate.
7. Resolve review comments.
8. Merge approved work.

## Branch Naming

Suggested patterns:

```text
feature/<short-description>
analysis/<short-description>
data/<short-description>
docs/<short-description>
fix/<short-description>
```

## Commit Messages

Prefer descriptive messages such as:

```text
Add customer activity transformation
Document loan status business rules
Fix duplicate transaction aggregation
Add portfolio KPI definitions
```

Avoid vague messages such as:

```text
update
changes
final
final2
stuff
```

## Contribution Evidence

Participants should ensure their work is visible through one or more of:

- commits;
- pull requests;
- code reviews;
- issues;
- documentation;
- analytical artefacts;
- recorded project decisions;
- presentation contribution.

The purpose is not to maximise commit counts. Evidence should reflect genuine contribution.

## Data Handling

Do not modify files in the raw-data area in place.

Derived datasets should be reproducible from documented code or transformation steps wherever practical.

## Team Decisions

Material decisions about metric definitions, exclusions, model design or scope should be recorded in the repository rather than existing only in private messages.
